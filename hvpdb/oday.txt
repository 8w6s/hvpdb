## I. CHECKPOINT & WAL

### 🔴 CRITICAL BUG #1: Auto-Checkpoint Dead Code

| Field | Value |
|-------|-------|
| **File:Line** | `storage.py:300-319` |
| **Type** | Logic Bug |
| **Severity** | CRITICAL |

**Code:**
```python
# storage.py:300-319
def commit(self):  # HVPStorage.commit() - KHÔNG BAO GIỜ được gọi
    if not self.durable:
        return
    try:
        if os.path.exists(self.log_path) and os.path.getsize(self.log_path) > self.wal_checkpoint_threshold:
            self.save()  # ← DEAD CODE
            return
    except OSError:
        pass
```

**Write path thực tế:**
```python
# core.py:334-338 - insert()
self.storage.append_log('insert', ...)  # ← Gọi wal.append()
self.storage.commit_txn(txn_id)          # ← Gọi wal.write_batch()

# storage.py:336-351 - commit_txn()
def commit_txn(self, txn_id: str):
    self.wal.write_batch(self._txn_buffers[txn_id])  # ← KHÔNG check threshold
```

**Proof:**
```bash
$ rg -n "storage\.commit\(\)" *.py
# → NO MATCHES FOUND
```

**Risk:** WAL grow unbounded → Disk full → Crash

**Fix:**
```python
# storage.py:336 - Trong commit_txn(), thêm:
def commit_txn(self, txn_id: str):
    # ... existing code ...
    del self._txn_buffers[txn_id]
    # Thêm threshold check:
    try:
        if os.path.getsize(self.log_path) > self.wal_checkpoint_threshold:
            self.save()
    except OSError:
        pass
```

## IX. PRODUCTION RISK ANALYSIS

### 🔴 CRITICAL: WAL Unbounded Growth

| Scenario | Impact |
|----------|--------|
| Long-lived process (Discord bot) | WAL → Disk full |
| No explicit save() call | WAL never truncated |
| Auto-commit disabled | WAL grows linearly |

**Mitigation:** None in code

---

### 🔴 CRITICAL: Data Loss on Crash

| Scenario | Result |
|----------|--------|
| Crash after `append_log()` before `fsync()` | Data loss |
| Crash after `fsync()` in WAL but before `save()` | Recoverable via replay |
| Crash during `save()` | Old file intact (atomic replace) |

**Verdict:** WAL provides durability, but only if process calls `save()` periodically

---

### 🟡 MEDIUM: Restart Time Scaling

| Records | WAL Size | Restart Time |
|---------|----------|--------------|
| 100K | ~50MB | ~1-2s |
| 1M | ~500MB | ~10-20s |
| 10M | ~5GB | ~100-200s |

**Analysis:** Replay O(n) where n = WAL entries since last save

---

### 🟡 MEDIUM: OOM on Large Dataset

| Records | Est. RAM |
|---------|----------|
| 100K | ~50-100MB |
| 1M | ~500MB-1GB |
| 10M | ~5-10GB |

**Analysis:** No lazy loading → Hard limit on dataset size
